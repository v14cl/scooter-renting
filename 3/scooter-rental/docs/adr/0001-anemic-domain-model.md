# ADR 0001: Обрати Anemic Domain Model

## Статус
Прийнято

## Контекст
Для лабораторних робіт потрібні:
- окремі доменні моделі, не залежні від ORM;
- фабрики домену для перевірки інваріантів;
- чітка шарова архітектура;
- можливість легко перейти до CQS/CQRS.

## Рішення
Обрати підхід **Anemic Domain Model**:
- доменні моделі зберігають стан;
- інваріанти перевіряються у value objects та domain factories;
- orchestration живе в application handlers;
- мапінг між ORM і доменом виконується в infrastructure.

## Обґрунтування
- Менше коду для поточної лабораторної.
- Простіше писати ізольовані unit-тести для фабрик і use case handlers.
- Перехід до окремих CommandHandler / QueryHandler майже не потребує зміни доменних класів.
- Добре підходить для навчального CRUD-проєкту з чіткими інваріантами.

## Наслідки
- Частина поведінки буде розподілена між фабриками та application layer.
- Якщо домен стане суттєво складнішим, можливий перехід до Rich Domain Model у майбутньому.
