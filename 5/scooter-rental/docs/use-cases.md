# Юзкейси системи прокату електросамокатів

## 1. Реєстрація користувача
- Назва: Реєстрація користувача
- Актор: Гість
- Передумови:
  - Користувач ще не зареєстрований у системі.
  - Email не зайнятий іншим акаунтом.
- Основний сценарій:
  1. Гість надсилає ім'я, email і пароль.
  2. Система перевіряє валідність email і обов'язковість полів.
  3. Система перевіряє унікальність email.
  4. Система створює користувача з роллю `CUSTOMER`.
  5. Система повертає JWT-токен і дані користувача.
- Альтернативні сценарії / помилки:
  - Email невалідний -> `400 Bad Request`.
  - Email уже існує -> `409 Conflict`.
  - Порожні поля -> `400 Bad Request`.

## 2. Вхід у систему
- Назва: Вхід у систему
- Актор: Зареєстрований користувач
- Передумови:
  - Користувач існує в системі.
- Основний сценарій:
  1. Користувач надсилає email і пароль.
  2. Система знаходить користувача за email.
  3. Система перевіряє пароль.
  4. Система повертає JWT-токен і дані користувача.
- Альтернативні сценарії / помилки:
  - Користувача не існує -> `401 Unauthorized`.
  - Пароль невірний -> `401 Unauthorized`.

## 3. Отримання профілю поточного користувача
- Назва: Перегляд власного профілю
- Актор: Авторизований користувач
- Передумови:
  - Користувач успішно увійшов у систему.
- Основний сценарій:
  1. Користувач викликає захищений ендпоінт профілю.
  2. Система визначає користувача з JWT.
  3. Система повертає дані профілю.
- Альтернативні сценарії / помилки:
  - JWT відсутній або невалідний -> `401 Unauthorized`.
  - Користувача не знайдено -> `404 Not Found`.

## 4. Створення самоката
- Назва: Створення самоката
- Актор: Адміністратор
- Передумови:
  - Адміністратор авторизований.
  - Код самоката унікальний.
- Основний сценарій:
  1. Адміністратор надсилає код, модель, заряд і ціну за хвилину.
  2. Система перевіряє інваріанти:
     - код не порожній;
     - заряд у межах `0..100`;
     - ціна за хвилину більша за нуль.
  3. Система створює самокат у статусі `AVAILABLE`.
  4. Система повертає створений ресурс.
- Альтернативні сценарії / помилки:
  - Код уже існує -> `409 Conflict`.
  - Невалідні поля -> `400 Bad Request`.
  - Користувач не авторизований -> `401 Unauthorized`.
  - Користувач не адміністратор -> `403 Forbidden`.

## 5. Перегляд списку самокатів
- Назва: Перегляд списку самокатів
- Актор: Авторизований користувач
- Передумови:
  - Користувач авторизований.
- Основний сценарій:
  1. Користувач запитує список самокатів.
  2. Система повертає всі самокати з їхнім статусом і ціною.
- Альтернативні сценарії / помилки:
  - JWT відсутній або невалідний -> `401 Unauthorized`.

## 6. Перегляд деталей самоката
- Назва: Перегляд деталей самоката
- Актор: Авторизований користувач
- Передумови:
  - Користувач авторизований.
  - Самокат існує.
- Основний сценарій:
  1. Користувач надсилає ідентифікатор самоката.
  2. Система повертає повні дані самоката.
- Альтернативні сценарії / помилки:
  - Самокат не знайдений -> `404 Not Found`.
  - JWT відсутній або невалідний -> `401 Unauthorized`.

## 7. Оновлення самоката
- Назва: Оновлення самоката
- Актор: Адміністратор
- Передумови:
  - Адміністратор авторизований.
  - Самокат існує.
- Основний сценарій:
  1. Адміністратор надсилає нові значення полів самоката.
  2. Система перевіряє інваріанти та унікальність коду.
  3. Система зберігає зміни.
  4. Система повертає оновлений ресурс.
- Альтернативні сценарії / помилки:
  - Самокат не знайдений -> `404 Not Found`.
  - Код конфліктує з іншим самокатом -> `409 Conflict`.
  - Невалідні поля -> `400 Bad Request`.
  - Немає прав адміністратора -> `403 Forbidden`.

- Альтернативні сценарії / помилки:

## 9. Створення бронювання самоката
- Назва: Створення бронювання
- Актор: Клієнт
- Передумови:
  - Користувач авторизований.
  - Самокат існує та доступний.
  - Часовий слот ще не зайнятий.
- Основний сценарій:
  1. Клієнт надсилає ідентифікатор самоката, початок і кінець бронювання.
  2. Система перевіряє інваріанти:
     - `start < end`;
     - `start` не в минулому;
     - самокат у статусі `AVAILABLE`;
     - немає перетину з іншими бронюваннями цього самоката.
  3. Система створює бронювання для поточного користувача.
  4. Система повертає створений ресурс.
- Альтернативні сценарії / помилки:
  - Самокат не знайдений -> `404 Not Found`.
  - Слот перетинається з іншим бронюванням -> `409 Conflict`.
  - Часовий діапазон невалідний -> `400 Bad Request`.
  - Самокат недоступний -> `409 Conflict`.

## 10. Перегляд списку бронювань
- Назва: Перегляд списку бронювань
- Актор: Авторизований користувач
- Передумови:
  - Користувач авторизований.
- Основний сценарій:
  1. Користувач запитує список бронювань.
  2. Якщо роль `ADMIN`, система повертає всі бронювання.
  3. Якщо роль `CUSTOMER`, система повертає лише власні бронювання.
- Альтернативні сценарії / помилки:
  - JWT відсутній або невалідний -> `401 Unauthorized`.
